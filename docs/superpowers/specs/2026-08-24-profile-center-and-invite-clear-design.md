# 个人中心页与换号邀请码清理

**日期：** 2026-08-24  
**状态：** 已确认，待写实现计划  
**端：** Android App + 微信小程序（行为对等）  
**相关：** 云同步/邀请码现位于「我的」；资料编辑现位于「设置」

## 1. 问题

1. **换号残留邀请码**：账号 A 生成邀请码后退出，再登录账号 B，界面仍显示 A 的邀请码。根因是邀请码存在页面内存（Android `MineViewModel.lastInviteCode`；小程序 `page.data.lastInviteCode`），`logout` 只清 JWT，不重制会话 UI。
2. **入口与资料分散**：用户希望从总览点头像进入「个人中心」；云同步、退出登录、改头像/昵称集中在个人中心；设置页不再放头像/昵称。

## 2. 已确认决策

| 项 | 选择 |
|----|------|
| 信息架构 | **新建独立「个人中心」页**（非 Tab）；「我的」Tab 仍保留 |
| 「我的」内容 | 只留账本管理 / 成员 / 健康色 / 导入导出 / 垃圾箱等；**去掉云同步与退出登录** |
| 「个人中心」内容 | 资料（头像更改 + 昵称）+ **整块云同步**（登录/退出、绑手机、上传、邀请码生成/展示/加入） |
| 「设置」 | **去掉**头像与昵称「资料」模块；保留版本（及小程序 AI Key 等） |
| 总览入口 | 顶栏右侧圆形头像 → 打开「个人中心」 |
| 换号清理 | 退出 / jwt·userId 变化时清**全部会话相关 UI**（邀请码、加入输入框、busy/错误文案等） |
| 邀请码存储 | 仍为内存态；**不按账号持久化** |
| 双端 | Android + 小程序同步改 |

## 3. 信息架构

```
总览 ──(点头像)──► 个人中心（新页）
                      ├─ 资料：头像、昵称
                      └─ 云同步：登录/退出/绑手机/上传/邀请码/加入
「我的」Tab ──────────► 账本与本地偏好（无云同步、无退出）
「设置」──────────────► 版本（+ 小程序 Key）；无资料卡
```

## 4. 会话清理行为

触发时机（任一即可，建议两者都做以免漏）：

1. 用户点击「退出登录」成功清 JWT 之后  
2. 观察到 `jwt` / `cloudUserId` 变为空，或变为**不同**用户

须清空的状态（双端对等）：

- `lastInviteCode`
- `inviteInput`（加入账本输入）
- 云同步 busy 文案 / 瞬时错误或 action toast 队列中与会话相关的提示（按现有模式清即可）

不删：本地账本数据、头像文件、昵称 prefs 的本地缓存策略（昵称是否跟账号走见既有 `nickname-follows-account` 设计；本需求不改其规则，仅移动编辑入口）。

## 5. Android 实现边界

| 项 | 说明 |
|----|------|
| 路由 | 新增 `Route.Profile`（如 `"profile"`），非 bottom tab |
| UI | 新 `ProfileScreen` + `ProfileViewModel`：迁入现 Mine 云同步 UI 与 Settings 资料编辑 |
| 总览 | `OverviewScreen` TopBar `actions` 增加头像，`onOpenProfile` → `navController.navigate(Route.Profile)` |
| 「我的」 | 删除云同步 Card 与退出；资料卡改为展示或弱入口（点头像/文案可进个人中心，可选）；保留设置齿轮 |
| 「设置」 | 删除资料 Card（头像+昵称）；保留版本等 |
| 清理 | `ProfileViewModel.logout` 与 `jwt`/`userId` Flow collect 时 `resetSessionUi()` |

## 6. 小程序实现边界

| 项 | 说明 |
|----|------|
| 页面 | 新 `pages/profile/profile`（js/wxml/wxss/json）；`app.json` `pages` 注册，**不进 tabBar** |
| 总览 | `overview` header-right 加头像，`navigateTo` profile |
| 「我的」 | 去掉云同步块与退出；可保留进设置入口 |
| 「设置」 | 去掉资料（头像/昵称）；保留版本与 AI Key |
| 清理 | `sync.logout` 后、以及 `refresh` 发现 jwt/userId 变化时清 `lastInviteCode` / `inviteInput` |

## 7. 文案与交互细节

- 个人中心标题：「个人中心」  
- 未登录：云同步区显示「去登录」；无邀请码区  
- 已登录：显示退出登录；生成邀请码后展示码并可复制分享文案（沿用 `InviteShareText` / `inviteShare.js`）  
- 总览头像：有本地头像则显示图，否则默认人像/首字占位；点击始终进个人中心（未登录也可进，在页内登录）

## 8. 测试要点

1. A 生成邀请码 → 退出 → 登录 B → 个人中心**无**旧码，加入输入为空  
2. A 生成邀请码 → 不退出直接杀进程再开（可选）：内存态丢失属预期  
3. 总览点头像 → 个人中心；可改头像、改昵称并保存  
4. 设置页无头像/昵称模块；版本仍可见  
5. 「我的」无云同步/退出；账本管理等仍可用  
6. 双端行为一致  

## 9. 非目标

- 不新建服务端接口  
- 不把邀请码写入 prefs / 按 userId 持久化  
- 不改变账本可见性 / 登录绑本弹窗（见 `2026-08-24-account-ledger-visibility-design.md`）  
- 不把「我的」从 tabBar 移除  

## 10. 开放项（实现时按惯例）

- 「我的」顶部资料卡：仅展示昵称/头像并跳转个人中心，或整卡删除只留设置入口——实现时优先**保留展示卡 + 点击进个人中心**，避免「我的」顶部空荡。  
- Android 头像组件：Overview / Profile / Mine 共用同一小组件，避免三份 Bitmap 解码逻辑。
