# 手机号登录、独立登录页与局域网开发环境

**日期：** 2026-08-21  
**状态：** 待用户确认  
**端：** Android + 微信小程序 + `renovation-ledger-server`  
**关联：** `docs/superpowers/specs/2026-08-14-cloud-login-and-auto-sync-design.md`（云同步、邀请仍有效；本 spec 修正登录入口与开发联调方式）

## 1. 目标与验收

### 1.1 用户要的效果

**场景 1 — 同一账号多端**

1. 电脑部署后端；设备与小程序均连该后端（同 WiFi 局域网）。
2. 用测试账号登录 → 上传/绑定一本账本。
3. 另一手机、小程序用**同一账号**登录 → 能拉到同一本账本。
4. 任一端改数据 → 其它端**重新进入**（进 App / 回前台 / 再进相关页）后看到更新。

**场景 2 — 不同账号协作**

1. 另一设备用**另一账号**登录。
2. 填写账号 A 生成的邀请码加入 → 可编辑该账本。
3. 改数据后，已加入的其它设备/小程序重新进入也能看到更新。

本期不做实时推送；以「重新进入时拉最新」为准。

### 1.2 本 spec 负责解决的缺口

| 缺口 | 处理 |
|------|------|
| 「开发登录」不能当稳定测试账号（各端 label 易不一致） | 改为手机号 + 验证码登录；同一手机号 = 同一用户 |
| 默认 `127.0.0.1` + `adb reverse` 不适合多机/小程序 | 开发环境默认电脑局域网 IP；去掉 USB 转发 |
| 登录按钮塞在「我的」 | 独立登录页；「我的」只留入口 |

云同步、上传绑定、邀请、条目推送：**沿用现有实现**，本 spec 不重做，只在验收里覆盖场景 1/2。

## 2. 产品流程与界面

### 2.1 独立登录页

- 路由：Android `login`；小程序 `pages/login/login`。
- 页内切换：**微信** | **手机号**（Tab 或分段控件）。
- **微信**：走现有 `POST /auth/wechat`。AppId 未配置时按钮可点，toast「微信登录暂不可用，请使用手机号登录」；不回退到开发登录。
- **手机号**：
  1. 输入 11 位手机号；
  2. 点「获取验证码」→ `POST /auth/sms/send`；
  3. **测试/开发环境**：响应含 `code`，客户端**自动填入**验证码框；
  4. 点「登录」→ `POST /auth/sms/login` → 写入 JWT / userId / phone；
  5. 成功后返回上一页（或回到「我的」）。
- 「我的」**不再**放置微信登录 / 开发登录按钮。

### 2.2 「我的」（未登录 / 已登录）

**未登录**

- 展示「未登录」+ 主按钮 **「去登录」** → 进入登录页。
- 无上传、邀请、绑手机（需登录的能力入口可灰显或点后引导去登录）。

**已登录**

- 展示登录态（昵称/手机号脱敏等，沿用现有信息即可）。
- 保留：上传当前账本（仅未绑云时）、生成/输入邀请码、绑定手机号（若仍无 phone 且走微信取号——与现网一致；手机号登录成功后通常已有 phone，可隐藏绑手机）。
- 增加 **「退出登录」**：清本地 JWT / cloudUserId / phone；不清本地账本数据。

### 2.3 可选登录

- 未登录可用本机账本（与现网一致）。
- 不强制启动进登录页。
- 云接口 401：清登录态，toast「请重新登录」；用户从「我的」进登录页。

## 3. 账号与接口

### 3.1 账号模型

- **同一手机号对应同一 `User`**（多端场景 1 的前提）。
- `POST /auth/sms/login`：若该手机号已有用户则发 JWT；否则创建用户并写入 `phone`，再发 JWT。
- 微信登录仍按 openid/unionid；若日后微信身份与已有手机号用户合并，沿用既有「绑同一手机号后合并」规则（本期不新做复杂合并 UI）。
- 手机号登录成功后，用户已带 `phone`，一般无需再点「绑定手机号」。

### 3.2 新接口（permitAll）

**`POST /auth/sms/send`**

请求：

```json
{ "phone": "13800138000" }
```

行为：

- 校验手机号格式；
- 生成随机验证码（建议 6 位数字），按 `phone` 缓存（TTL 如 5 分钟；同号重发覆盖旧码；可加简单频控）；
- **开发/测试 profile**（配置项如 `app.sms.return-code-in-response: true`）：响应体返回 `code`，便于客户端自动填入；
- **正式 profile**（`return-code-in-response: false`）：响应**不**含 `code`；本期可不接短信商，返回明确错误如「正式环境短信未开通」或 501，避免误以为已发短信。

成功响应（测试）：

```json
{ "expiresInSec": 300, "code": "482901" }
```

成功响应（正式、若已接短信）：

```json
{ "expiresInSec": 300 }
```

**`POST /auth/sms/login`**

请求：

```json
{ "phone": "13800138000", "code": "482901" }
```

行为：

- 校验缓存中该号验证码；错误/过期 → 401 或 400，文案「验证码错误或已过期」；
- 成功后使该码失效（一次性）；
- 查找或创建用户，返回与现网一致的 `AuthResponse`：`userId`、`token`、`nickname`、`phone`。

### 3.3 现有接口

| 接口 | 本 spec |
|------|---------|
| `POST /auth/wechat` | 保留；登录页微信 Tab 使用 |
| `POST /auth/bind-phone` | 保留（已登录后微信取号绑定） |
| `POST /auth/dev-login` | **产品路径不再调用**；服务端可暂留供自动化测试，`dev-login-enabled` 正式关闭。客户端去掉所有「开发登录」UI 与语音工具入口 |

### 3.4 Security

`SecurityConfig` 增加 permitAll：`/auth/sms/send`、`/auth/sms/login`。

## 4. 开发环境与去掉 adb reverse

### 4.1 默认地址

- 删除产品路径对 `http://127.0.0.1:18080/`（USB 转发）的依赖。
- **Debug 默认开发地址** = 打包写入的 `DEV_LAN_URL`（电脑局域网 IP + 后端端口，现有 `BuildConfig.DEV_LAN_URL`）。
- `CloudEnv.DEV_URL` 改为与 `DEV_LAN_URL` 同语义，或直接让 `urlOf(DEV)` 返回 `DEV_LAN_URL`；不再默认 `127.0.0.1:18080`。

### 4.2 开发面板（摇一摇，仅 Debug）

保留：

- 开发 / 正式切换；
- 服务器地址展示/编辑（换 NAS、正式 host 时用）；
- 测通（不写登录态）。

删除：

- 「USB 转发」芯片与相关文案；
- 一切 `adb reverse` 提示文案（含 `ApiErrorMessages`）。

测通：**不得写入登录态**。优先调用公开 `GET /health`（若服务端尚无则本期补一个只返回 ok 的接口）；禁止再用 `dev-login` 冒充测通。

连接失败文案改为：确认电脑服务已启动、手机与电脑同一局域网、地址是否为电脑 IP、防火墙是否放行端口。

### 4.3 小程序

- 开发版默认/可配置为电脑局域网 API 基址（与现有 env 切换一致）。
- 去掉「开发登录」按钮；未登录进独立登录页。

## 5. 客户端改动摘要

### 5.1 Android（`renovation-ledger`）

- 新增 `LoginScreen` + `LoginViewModel`；`AppNav` 增加 `login` 路由。
- `MineScreen`：未登录仅「去登录」；已登录加「退出登录」；删除开发登录与内嵌微信登录按钮。
- `LedgerApi` / `LedgerSyncRepository`：`sendSmsCode`、`smsLogin`；删除产品侧 `devLogin` 调用（含 `MineViewModel`、`DevLoginExecutor`）。
- `CloudEnv` / `DebugCloud*`：默认局域网；去掉 USB / adb reverse。
- `ApiErrorMessages`：去掉 adb reverse 文案。
- `WeChatAppAuth` 提示改为引导手机号登录，不再提「开发登录」。

### 5.2 小程序（`renovation-ledger-miniprogram`）

- 新增登录页；「我的」改为「去登录」。
- `sync.js`：发码、手机号登录；删除/停用页面上的 `devLogin`。
- 测试环境：发码响应有 `code` 则自动填入。

### 5.3 服务端（`renovation-ledger-server`）

- `AuthService` / `AuthController`：实现 sms send/login + 内存或缓存验证码存储。
- `application-local.yml` / test：`app.sms.return-code-in-response: true`。
- `application.yml`（正式默认）：`false`；正式未接短信时 send 明确失败。
- 单测：发码返回码（测试配置下）、错误码登录失败、同号多端拿到同一 `userId`。

## 6. 与云同步/邀请的衔接（不改语义）

登录成功后行为与现网一致：

1. 进 App / 回前台：`refreshOnOpen`（有 JWT 则拉列表 + pull 当前本）。
2. 未绑云：可「上传当前账本」→ `import` → 写 `cloudLedgerId`。
3. 已绑云：改条目后台 `pushItem`；他端再进时 pull 看到更新。
4. 邀请：OWNER 生成码；他账号 join 后本地带上该 `cloudLedgerId`。

场景 1/2 验收时，三端（两手机 + 小程序）API baseUrl 必须指向**同一台**电脑后端。

## 7. 错误处理

| 情况 | 行为 |
|------|------|
| 手机号格式非法 | 本地校验，不发请求 |
| 验证码错误/过期 | toast 服务端文案 |
| 发码过于频繁 | 服务端 429 或等价，toast |
| 正式环境未开通短信 | toast「正式环境短信未开通」 |
| 微信未配置 / 未安装 | toast，引导改用手机号 |
| 网络连不上局域网 | toast（无 adb reverse） |
| 401 | 清 JWT，引导去登录 |

## 8. 测试计划（验收）

1. 电脑启动 local 后端；两台手机与小程序 baseUrl 均为该电脑局域网地址。
2. 手机 A：登录页 → 手机号 → 获取验证码（自动填入）→ 登录 → 上传账本。
3. 手机 B、小程序：同一手机号走同样流程登录 → 列表/当前本能看到该账本；改一条 → 他端重新进入可见。
4. 手机 B：退出 → 另一手机号登录 → 输入 A 的邀请码加入 → 编辑 → A 与小程序重新进入可见。
5. 「我的」无开发登录；开发面板无 USB / adb reverse；Debug 默认地址为局域网。
6. 微信 Tab：无 AppId 时提示可用手机号，不崩溃。

## 9. 明确不做

- 真短信网关接入。
- 强制登录门闸。
- 实时 WebSocket/推送。
- 把 `dev-login` 包装成手机号登录。
- 本期合并微信身份与手机号身份的复杂产品流程（仅保留服务端既有冲突规则：手机号已被占用则 409）。

## 10. 决策记录

| 项 | 选择 |
|----|------|
| 登录形态 | 独立登录页；微信 + 手机号可切换 |
| 「我的」 | 不去内嵌登录按钮；「去登录」入口 |
| 登录是否强制 | 可选（本机可用） |
| 测试验证码 | send 接口返回随机码；客户端自动填入；login 校验该码 |
| 正式验证码 | 不回传码；本期可不接短信 |
| 开发默认地址 | 电脑局域网；去掉 USB / adb reverse |
| 开发登录 | 产品去掉；服务端可暂留测服用 |
| 双端 | Android + 小程序一起改 |
| 总验收 | 同号多端同步 + 邀请码跨账号协作 |
